Rider中使用AIAgent

目前，我是用ACP的方式，在Rider中使用AIAgent。ACP(Agent Client Protocal)可以理解为Editor <-> Agent的通信标准，Rider可以启动AI Agent程序让其作为内部的一个子程序运行。目前我的AIAgent用的是Cursor。

根据 Cursor 官方文档和 JetBrains 博客的说明，操作如下：

  1. 检查前置条件

    • 确保你的 Rider 版本在 2025.3.2 或更高，并且已经启用了内置的 AI Assistant 插件。
    • 你需要一个付费的 Cursor 订阅账户。

  2. 从 ACP 注册表安装 Cursor

    • 在 AI Chat 面板中，找到并打开代理提供者（Agent Provider）列表。

    • 选择 Add Agent from Registry（从注册表添加代理）。

    • 在弹出的列表中搜索 Cursor，然后点击安装。

  3. 身份验证

    • 安装完成后，在代理提供者列表中选择 Cursor 作为你的 AI 代理。
    • 根据提示完成登录和身份验证流程。

  4. 开始使用

    • 验证成功后，你就可以在 AI Chat 面板中直接向 Cursor 的 Agent 发送指令了。Cursor 可以读取你的项目文件、编辑代码，并在 IDE 的集成终端中运行命令。

MCP for Unity

MCP

MCP（Model Context Protocal）是个协议，由Anthropic提出，用于AI应用（比如我的Cursor客户端）和外部软件之间的连接。官方文档：What is the Model Context Protocol (MCP)?

在连接这件事情上，MCP提出了三个概念用于区分角色：

  1. Host，AI应用
  2. Client，Host内嵌的连接器
  3. Server，外部软件按照MCP的规矩暴露出的能力服务

其中，Client在Host中有多个，通过HTTP和Server一对一连接，并且使用json作为消息格式。

MCP规定Server暴露的核心信息有三种：

  • Tools（工具）：AI 可以调用的可执行函数（如“查数据库”、“发邮件”）。由模型决定何时调用，但有副作用。
  • Resources（资源）：提供给 AI 的只读数据源（如文件内容、数据库记录）。由宿主或用户控制读取时机，无副作用。
  • Prompts（提示词模板）：服务端预定义的可复用交互模板（如工作流脚本）。由用户显式触发。

如何配置

有了上面的相关概念，我们在配置的时候，就可以抓中重点。Host即Agent本身里内嵌Client，不需要我们来管，在连接这件事上，只需要重点关注Server：1）Server的目标Client；2）Server的配置文件；3）Server的运行

  1. Unity编辑器中安装MCP for Unity

    PackageManager左上方+号 有个Add Package from git URL

    输入链接：https://github.com/CoplayDev/unity-mcp.git?path=/MCPForUnity#main

    这里，#main可以替换为指定的版本比如#v10.3.0。

  2. 打开MCP for Unity窗口并配置Server

    如下图所示，在Client Configuration中，选择指定的Agent Client，我这里用的Cursor，然后点击Configuration All Detected Clients，会自动配置在Agent客户端中配置Server的配置文件，用于连接Agent客户端中的Client。在Server中，点击Start Server，开始连接Agent。

  3. Agent客户端验证

    在我们的Agent客户端的设置中的MCP中，可以看到多了一个MCP的配置文件，并且是绿色状态，说明已经通过HTTP连上了MCP for Unity的Server。并且，我们可以unityMCP的Server，显示Tools有多少个，Resourses有多少个，这正是MCP所规定Server应该暴露的能力。

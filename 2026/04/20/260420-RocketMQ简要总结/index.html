RocketMQ简要总结

loudmute
2026-04-20
后端开发 › 中间件
中间件, 消息队列

RocketMQ是阿里巴巴开源的分布式消息中间件，简单来说就是一个消息队列，生产者将消息发送到Broker，消费者从Broker拉取消息进行处理，从而实现系统之间的异步通信和解耦。

核心组件

RocketMQ由Broker、NameServer、Producer、Consumer四个核心组件组成。

  • Broker：负责存储和转发消息
  • NameServer：维护Broker的路由信息（即哪些Topic分布在哪些Broker上），为Producer和Consumer提供寻址服务
  • Producer：创建并发送消息到Broker
  • Consumer：从Broker拉取消息并进行业务处理

消息模型

RocketMQ的消息模型包含三个核心要素：Topic、MessageQueue、Message。

  • Topic（主题）：消息的逻辑分类，生产者将消息发送到 Topic，消费者从 Topic 订阅消息
  • MessageQueue（消息队列）：Topic 的物理分片，每个 Topic 可以划分为多个 Queue，是消息存储和消费的最小单元，用于负载均衡和顺序性
  • Message（消息）：实际传输的数据单元，包含 Topic、Tag、Key、消息体（Body）和用户属性等

除此之外还有一些概念：

  • Tag：消息的二级标签，用于在同一 Topic 下更细粒度地过滤消息
  • ConsumerGroup：一组消费者的逻辑集合，集群模式下组内消费者共同分担 Queue，一条消息只被一个消费者消费
  • ProducerGroup：一组生产者的逻辑集合，主要用于事务消息回查

消息的逻辑分类是Topic，消息实际存储在Broker中，Topic和Broker是多对多的关系，并且一个Topic的多个MessageQueue可能分布在多个Broker中。

消息

在 RocketMQ 中，消息（Message） 是系统中最基本的数据单元，是生产者发送给 Broker、消费者从 Broker 拉取并处理的核心对象。

消息的组成

RocketMQ 的消息对象是 org.apache.rocketmq.common.message.Message，主要包括以下字段：

字段 说明
Topic 消息所属的主题，决定消息被哪个消费组消费
Flag 标志位，通常不用
Properties 消息属性（键值对），可包含 Tag、Key、自定义业务属性等
Body 消息体，字节数组，承载实际业务数据（如 JSON、字符串等）
TransactionId 事务消息的事务 ID（可选）

常用属性（Properties 中的键）：

  • KEYS：消息的业务键（如订单号），用于查询和回溯。
  • TAGS：消息标签，用于消费端过滤。
  • WAIT、DELAY 等：延迟消息相关属性。
  • 自定义属性：生产者可以通过 putUserProperty() 添加任意业务信息。

消息的类型

RocketMQ 支持多种类型的消息，以适应不同业务场景：

类型 描述 关键实现
普通消息 无序、并发消费，吞吐最高 默认发送即可
顺序消息 局部顺序或全局顺序，保证同一业务 ID 的消息按发送顺序消费 通过 MessageQueueSelector 将相同业务键的消息路由到同一个 Queue，消费者单线程消费该 Queue
延迟消息 发送后延迟指定时间才被消费 设置 delayTimeLevel（1~18 级），Broker 内部使用 SCHEDULE_TOPIC_XXXX 暂存，到期后投递
事务消息 保证本地事务与消息发送的最终一致性 两阶段提交（半消息）+ 回查
批量消息 多条消息打包发送，提高吞吐 同一 Topic，总大小不能超过限制（默认 4MB）
过滤消息 消费者按 Tag 或 SQL 表达式过滤 Broker 端过滤，减少网络传输

底层存储

RocketMQ 的底层存储是其高性能与高可靠性的核心，主要围绕CommitLog、ConsumeQueue、IndexFile三类文件进行设计。

文件 作用 特点
CommitLog 存储所有消息的原始数据（消息体、属性、Topic、QueueId等） 所有消息顺序写入同一个文件，单个文件默认1GB，写满自动新建
ConsumeQueue 消息的逻辑队列索引，按 Topic-Queue 划分 每条记录固定20字节，保存消息在CommitLog中的偏移量、大小、Tag哈希
IndexFile 按消息 Key 或时间范围查询的索引 可选，支持快速消息回溯

核心思想：

  • 写：无论Topic如何，所有消息都顺序追加到CommitLog，利用磁盘顺序写的高性能。
  • 读：消费者先读轻量级的ConsumeQueue（相当于索引），再根据偏移量定位CommitLog读取完整消息，避免全量扫描。

项目集成

我在秒杀项目中，使用RocketMQ来进行异步削峰，将接应秒杀请求和处理请求解耦，以确保流量不会打垮系统，消费者可以按自己能力平稳处理秒杀请求。

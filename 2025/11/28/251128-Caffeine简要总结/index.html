Caffeine简要总结

loudmute
2025-11-28
后端开发 › 中间件
中间件, 消息队列

Caffeine 是一个基于 Java 8 的高性能、近乎最优的缓存库，是 Guava Cache 的继承者和改进版。它提供了灵活的缓存策略、极高的命中率和极低的延迟，被广泛应用于 Spring Boot 等现代 Java 项目中。

一、核心特性

  1. 高性能

    Caffeine 的读写吞吐量在绝大多数场景下优于 Guava Cache、Ehcache 等，接近理论最优值。

  2. 灵活的驱逐策略

    • 基于大小（maximumSize、maximumWeight）
    • 基于时间（expireAfterWrite、expireAfterAccess、expireAfter）
    • 基于引用（弱引用、软引用）
    • 支持自定义驱逐策略（weigher）

  3. 自动加载与刷新

    • 同步加载：LoadingCache
    • 异步加载：AsyncLoadingCache
    • 支持 refreshAfterWrite 自动刷新过期条目（懒刷新）

  4. 统计功能

    通过 recordStats() 开启命中率、加载耗时等统计信息，便于监控。

  5. 基于 W-TinyLFU 的准入策略

    Caffeine 使用 Window TinyLFU 算法，结合了 LRU 和 LFU 的优点，能自适应访问模式，获得极高的缓存命中率。

三、常用配置参数

参数 说明
initialCapacity 初始容量，影响内部哈希表大小
maximumSize 最大条目数，超过后按策略驱逐
maximumWeight 最大权重（需配合 weigher 使用）
expireAfterWrite 写入后固定时间过期
expireAfterAccess 最后一次访问后固定时间过期
expireAfter(Expiry) 自定义过期策略（更灵活）
refreshAfterWrite 写入后自动刷新（懒刷新）
weakKeys / weakValues 键/值使用弱引用
softValues 值使用软引用（不推荐，性能差）
recordStats 开启统计（需引入 caffeine-stats 模块，或使用 Caffeine.recordStats()）
executor 指定异步加载/刷新使用的线程池
removalListener 条目被移除时的监听器

五、W-TinyLFU 算法（简单了解）

Caffeine 采用 Window TinyLFU 作为默认的准入策略，它结合了：

  • Window LRU：最近窗口（少量条目）使用 LRU，快速响应突发流量。
  • TinyLFU：使用 Count-Min Sketch 记录访问频率，优先保留高频条目，过滤低频一次性数据。
  • SLRU（Segmented LRU）：主缓存分为“试用期”和“保护期”两段，只有进入保护期的条目才可能长期驻留。

这种组合使得 Caffeine 在多种访问模式下都能获得接近最优的命中率，同时保持较低的内存开销。

六、与 Guava Cache 的对比

特性 Caffeine Guava Cache
性能 更高（接近最优） 较好
驱逐算法 W-TinyLFU LRU
异步缓存 原生支持 AsyncCache 不支持
自动刷新 refreshAfterWrite（懒） refreshAfterWrite
统计信息 更详细 基本统计
维护状态 活跃 已停止更新

Guava Cache 已进入维护模式，官方推荐迁移到 Caffeine。

Caffeine 是一个功能强大、性能卓越的本地缓存库，特别适合在 Spring Boot 项目中使用。它提供了丰富的缓存策略、自动加载/刷新、异步支持和详尽的统计，能有效提升应用性能和响应速度。合理配置 Caffeine 的容量、过期和刷新参数，是使用好它的关键。

Java-面向对象

loudmute
2025-08-05
后端开发 › Java
Java

Java OOP 的核心是：把数据和操作封进类；用继承和接口做扩展；运行时通过多态选真正实现；再用封装和访问控制保证安全；用 equals/hashCode、final、抽象类/接口这些规则把行为约定清楚。

知识脉络：

-> 类与对象：是什么、构造

-> 三大特性: 封装 -> 继承 -> 多态 (怎么组织代码)

-> 方法关系：重载(同类扩展) vs 重写(子类覆盖)

-> 抽象：抽象类/接口(定规范、定模板)

-> 修饰与约束：static / final / this / super / access)

类与对象

类是一种模板，定义字段和数据；对象是类new出来的实例。

类信息一份在方法区，对象在堆区，引用在栈区。

定义一个类意味着约定一种类型：有哪些数据，有哪些方法。

一个类被编译为.class，加载到JVM内存里才有可用的类信息。

构造方法

构造方法（构造器）是用来创建对象时自动调用的特殊方法，用户初始化对象。

特点：1）名字和类名相同；2）无返回类型；3）不能被继承，但子类可以通过super(...)调用父类的构造方法。

没有写构造器时，编辑器自动生成默认的无参构造器。

写了构造器时，不会自动生成，要用到无参构造器时需要自己写。

可以重载，一个类可以有多个构造方法，参数列表不同，还可用this(...)调用本类其他构造方法。

不可以重写，构造方法不能被继承，只是子类可以通过 super(...) 调用父类的构造方法。

子类构造时一定要先初始化父类部分。

1）子类构造第一行必须有super(...)或者this(...)

2）若没有，编译器自动插入super()

3）父类没有无参构造时，子类必须显示super(...)

三大特性

三大特性

面向对象的三大特性是：封装、继承、多态。

封装就是把字段和方法隐藏在对象内部，不允许外部直接访问对象内部信息，提供可供外部使用的方法。

-> 1) 隐藏内部信息；2）提供可用方法；3）保护数据安全

继承就是子类复用父类结构，并扩展自己的字段和方法。

-> 1）代码复用；2）功能扩展；3）单继承限制

多态就是同一父类引用，指向不同子类对象，调用重写方法是走运行时实际类型（动态绑定）。

-> 1）分类应用指向子类对象；2）动态绑定；3）重写方法

封装让对象有了结构 -> 结构可以通过继承复用，并出现了父类和子类的垂直关系 -> 多态利用父类和子类的关系，通过父类同一引用，而子类对象在运行时可以表现不同的行为。

向上和向下转型

向上转型 是 子类对象 被 父类变量 引用。

向下转型 是 指向子类对象的父类引用 强制转换为 子类引用。

向上转型，安全、便于统一处理，编译时统一引用，运行时看实际类型，配合重写，就是多态的体现。

向下转型，有风险需保证类型匹配(instanceof)、为了使用子类特有属性，编译时就可以在代码中使用子类特有属性，运行时检查类型。

被引用的对象始终没变，变的是引用变量的编译器类型。

重载和重写

重载(Overload)就是同一类中多个同名方法根据不同的传参执行不同的逻辑处理。

重写(Override)就是子类对父类方法的重新改造，外部样子不能变，内部逻辑可以变。

重载和重写的区别：

1）范围：重载发生在同类中；重写发正在继承关系中

2）方法签名：重载的方法名相同、参数列表必须不同；重写的方法签名必须相同。

3）返回类型：重载的返回类型可以不同；重写的返回类型必须相同，或是原返回类型的子类型。

4）访问修饰符：重载的可以不同；重写的子类方法访问权限 >= 父类方法访问权限

5）绑定时期：重载方法是静态绑定；重写方法是动态绑定；

关于重写：

  1. 方法名、参数列表必须相同，子类方法返回值类型应比父类方法返回值类型更小或相等，抛出的异常范围小于等于父类，访问修饰符范围大于等于父类。
  2. 如果父类方法访问修饰符为 private/final/static 则子类就不能重写该方法，但是被 static 修饰的方法能够被再次声明。
  3. 构造方法无法被重写
  4. 如果方法的返回类型是 void 和基本数据类型，则返回值重写时不可修改。但是如果方法的返回值是引用类型，重写时是可以返回该引用类型的子类的。

抽象类和接口

抽象类

抽象类是一种不能被实例化的类模板。

  • 用abstract 修饰类
  • 可以有抽象方法（只有声明没有方法体、子类必须实现）
  • 也可以有实例字段、普通方法、构造器

接口

接口是一种能力约定，规定能做什么。

  • 用interface定义
  • 方法默认是抽象的（Java8可以定义default/static，Java9还有private）
  • 字段默认是 public static final （常量）
  • 一个类可以实现多个接口

抽象类和接口的区别

抽象类是模板（身份 + 可复用代码）-是什么-所属关系，接口是契约（能力）-怎么做-能力。

抽象类 接口
目的 「是什么」+ 可抽公共实现 「能做什么」
继承/实现 单继承（extends 一个类） 可实现多个
字段 可有普通实例字段 一般是常量（public static final）
构造器 有 无
方法 抽象 + 普通方法都可 抽象 + default/static 等
设计关系 垂直的类层次 水平的能力组合

选择：

  • 需要共享字段、构造逻辑、部分默认实现，且是「一种东西」→ 抽象类
  • 需要多种来源的能力、多组合 → 接口
  • 很多框架：接口对外，抽象类对内抽公共代码（如集合里的 List + AbstractList）

一个类只能继承一个抽象类，而一个类可以实现多个接口。这决定了，子类继承自一个抽象类的关系是垂直的，一个类实现多个接口的关系是水平的。

抽象类决定“是什么”以及部分的“怎么做”（公共字段和公共方法），而接口决定“能做什么”。当我们描述各种各样的动物时，我们可以从两个角度来描述：1）是什么 2）能做什么。“动物”一词就是抽象类，各种各样的动物都会有一致的东西（公共字段）比如器官、名字、年龄，都会有一致的行为（公共方法）比如摄取影响、身体衰老等，这是从“是什么”的角度来描述。我们也可以用“能做什么”来描述，比如能跑的（接口一）有猫、狗、虎、豹，比如能飞的（接口2）有鸟、飞机、宇宙飞船。

也就是说，抽象类强调所属关系，接口强调功能。

由抽象类和具体类构成的继承的垂直关系，不同的子类最终都会溯源到相当的父类；而由接口的具体类构成的实现的水平关系，不同的子类未必会有相同的父类。

在Java的各种各样的框架中，具体类、抽象类、接口，三者的分工往往是这样的：

  • 接口：做什么，是拿来用的
  • 抽象类和具体类：怎么做，是负责实现的

所以一个复杂的框架，对于它的使用者来说，往往就是调用接口；对于它的实现者来说，则需要考虑接口、抽象类和具体类。

以集合框架为例，我们要使用一种集合类型时，往往使用接口类型的引用来进行各种调用。
